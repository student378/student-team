AI는 ‘말로 설명하면 결과물을 만들어 주는 동료’에 가깝습니다.

우리가 하는 일말로 요청하기

“학생이 휴대폰으로 신청하고, 나는 관리자 화면에서 승인하고 싶어”처럼 업무 그대로 설명합니다. 이 요청문을 프롬프트라고 부릅니다.

담당자4. 화면을 인터넷에 올리기

화면 파일에 서버 주소를 넣고 GitHub Pages에 올리면, 학생이 휴대폰으로 열 수 있는 주소가 생깁니다.

화면 파일 (HTML)+…/exec 서버 주소›GitHub Pages에 올리기›학생 휴대폰에서 열리는 주소

"천원의 아침밥" 학생 신청 시스템을 만들 거야. 구성은 3개 파일이야.
21) 학생 신청 화면 index.html
2) 관리자 화면 admin/index.html
3) 서버 gas/Code.gs (구글 Apps Script 웹 앱, 구글 스프레드시트를 DB로 사용)
꼭 지킬 원칙:
3- 관리자 비밀번호를 HTML/JS 파일에 절대 쓰지 마.
- 학생 화면의 검사는 우회될 수 있으니, 같은 검사를 서버에서도 반드시 해.
4- 모르는 것은 지어내지 말고 나에게 물어봐. 테스트하지 않은 것을 "테스트했다"고 말하지 마.
5- 내가 해야 할 일을 초보자 눈높이로 번호를 붙여 설명해.
1
역할과 내 수준을 먼저 알려 주기

“너는 웹 개발자, 나는 비전공자”라고 밝히면 설명의 눈높이가 맞춰집니다.

2
결과물의 모양을 정해 주기

파일 3개와 각 파일의 역할을 정해 두면, 빠지는 화면이 없습니다.

3
보안 원칙을 미리 못 박기

비밀번호는 화면 코드에 쓰지 않고, 학생 화면의 검사는 서버에서도 다시 합니다.

4
정직하게 일하도록 정하기

모르면 물어보고, 테스트하지 않은 것은 했다고 말하지 않게 합니다.

5
내가 할 일을 번호로 받기

설치·배포처럼 사람이 할 일을 초보자 눈높이의 순서로 받습니다.

08 · 시작하는 법

우리 부서에서 시작해 보려면

코딩 지식보다 업무를 정확히 아는 것이 더 중요했습니다.

1업무 흐름을 먼저 말하기

누가 입력하고, 누가 확인하고, 무엇을 집계하는지. 화면 모양보다 업무 순서가 먼저입니다.

2한 번에 다 시키지 않기

서버 → 학생 화면 → 관리자 화면 → 검증처럼 단계를 나누면 빠지는 기능이 줄어듭니다.

3“지어내지 말고 물어봐” 넣기

모르는 정보는 질문하게 하고, 테스트하지 않은 것은 했다고 말하지 말라고 미리 정해 둡니다.

4검토를 따로 요청하기

“전반적으로 오류나 버그가 없는지 검토 및 분석”처럼 점검만 따로 시키면 숨은 문제가 드러납니다.

5책임 있는 문구는 직접 정하기

개인정보 보유 기간, 동의 문구는 담당 부서 기준으로 사람이 정해서 넣습니다.

6잘 된 방식을 재사용하기

“천원의 아침밥에서 한 작업을 똑같이 해 줘”처럼 앞선 작업을 기준으로 삼으면 다음 앱이 빨라집니다.
